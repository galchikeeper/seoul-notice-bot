# 서울 임대주택 공고 알림 봇

서울 공공지원민간임대·청년안심주택의 신규 모집공고를 매일 아침(+금요일 저녁)에 찾아
**카카오톡으로 카드 이미지째** 보내준다. GitHub Actions 에서 돌기 때문에
내 컴퓨터가 꺼져 있어도 동작한다.

```
소스 확인 → 신규 판정 → 공고문 PDF 파싱 → 카드 PNG 렌더
        → 저장소 커밋(=이미지 공개 주소 확보) → 카카오톡 피드 발송
```

## 감시 대상

| 소스 | 읽는 방법 |
|---|---|
| 서울시 청년안심주택 모집공고 | 게시판이 쓰는 JSON API 직접 호출 |
| 힐스테이트 관악 뉴포레 공지사항 | HTML 파싱, 처음 보는 글(등록일·제목) 중 모집공고만 |
| ~~공간지원리츠 5개 단지~~ | **공간지원리츠는 맥북 housing-local 에서 확인(해외 IP 차단)** — 2026-11-19부터 이 봇은 확인하지 않음(`SPACEREITS_ENABLED` 기본 `0`, `1` 이면 되살아남) |
| SH 주택임대 공고 | 게시판 HTML, 처음 보는 글 중 조건(청년·신혼·주거용)에 맞는 모집공고만 |
| 롯데 엘리스 모집공고 | 사이트 내부 목록(JSON), 서울·근교 7곳 단지의 모집공고만 (접수 현황·마감 글 제외). 공고문이 이미지라 표 칸을 글자 인식(`elyes_ocr.py`, tesseract 한국어)으로 읽어 타입·보증금·월세·층·향·용도·전용면적·신청기간·발표·계약 일정을 카드에 넣는다. 못 읽으면 '공고문 확인' + 상세 페이지 링크. **신청 마감(공고문 표 → 제목 '접수기간' 순)이 지났으면 보내지 않고**, 마감을 못 찾으면 '⏰ 마감일 확인 필요'로 보낸다. 전용면적이 적힌 공고는 30㎡ 기준을 똑같이 적용 |
| 마이홈 공공데이터 API (data.go.kr 15108420) | Secret `MYHOME_API_KEY`. 서울+경기 공공임대 모집공고 중 범위 안만. 면적이 없어 항상 `📐 면적 확인 필요`, 금액은 원 단위가 분명할 때만 만원으로(그 밖은 `확인 실패`). 다른 출처와 제목이 같으면 한 번만 알림. 공공지원민간임대(청년안심주택)는 이 API 에 없음 |

**자격 조건(2026-11-23)**: 모든 카드에 자격 2열 표(자격 | 내용)를 임대조건 표 바로 아래에 붙인다(`eligibility.py`, 사이에 다른 줄 없음). 행은 묶어서 짧게: 대상(나이·무주택·성별, 대상별로 다르면 '청년 … / 신혼 …') / 소득·자산·차량(공고문 금액 그대로 — 예: 소득 월평균 100·110·120%(1~3순위), 자산 청년 2억 5,100만 / 신혼 3억 4,500만, 차량 4,542만 원 이하. 못 읽은 항목만 '공고문 참고') / 거주 / 공급 (+ 입주 / 제한). 공고에 없는 항목은 행을 만들지 않고, 판정은 하지 않는다. 내용 칸은 줄바꿈(`is_wrapped`)이라 '…'로 잘리지 않게 했고, 그래도 잘리면 워크플로 env `ELIG_SPLIT: "1"` 로 '소득' / '자산·차량' 두 행으로 나눈다. 슬랙이 표 두 개를 거절하면 네모 칸(코드 블록)으로 자동 전환. 임대조건 표가 전부 '확인 실패'면 표 대신 '임대조건: 공고문 확인' 한 줄.

청년안심주택 카드의 평형·보증금·월세는 공고문 PDF 의 [공급현황] 표에서만 읽는다(`pdfparse.py`). 단위는 숫자 크기로 원/만원을 판별하고, 표를 못 읽으면 "확인 실패"로 비운다. 시험: `python -m unittest discover tests`.
지역 범위: 서울 전역 + 경기 과천·안양·성남·광명·의왕·군포·하남(2026-11-19 정함). 마이홈포털 웹사이트는 GitHub 실행 환경에서 접속이 막혀(2026-11-18 점검) 대신 공공데이터 API 를 쓴다.

**마이홈 카드는 맥북이 보낸다(2026-11-24).** 봇은 마이홈 공고를 찾고 중복을 거른 뒤 카드를 보내지 않고
`state.json` 의 `myhome_queue` 에 넣는다(`MYHOME_ON_MAC=0` 이면 예전처럼 여기서 보냄). 맥북의
`galchi-automations/housing-local/myhome_local.py`(launchd `com.galchi.myhome`, 08~22시 매시 5분)가 origin/main 의
대기열을 읽어 한국 IP 로 공고 페이지를 읽고 같은 관문을 거쳐 #임대주택 에 보낸다. 보낸 기록은 맥북 쪽 `myhome_state.json`.
myhome.go.kr robots.txt 가 공고문 내려받기(`/hws/com/fms/cvplFileDownload.do`)를 금지해서 이 프로그램이 직접 받지는 않는다.
맥북(`MYHOME_ASIDE=1`)에서는 사용자 지시(2026-11-24)로 사용자 브라우저(Aside CLI)가 공고 페이지의 공고문 링크와 같은 요청으로
공고 1건에 한 번, 최대 2파일을 받는다(`reader.aside_myhome_files`). 전용면적은 공고 페이지 공급 목록, 매입임대는 공고문의 가구원수별 기준.
관문은 마이홈 카드의 면적 빈 칸·금액 전부 빈 칸도 실패로 잡는다.

(예전 기록) 마이홈포털 웹사이트는 robots 정책으로 접근이 막혀 제외했다 — 2026-11-24 robots.txt 는 `Allow: /` 에
내려받기 주소 하나만 금지. 목록은 계속 공공데이터 API 로 받는다. 여기 뜨는 서울 공고는
결국 단지 홈페이지에도 올라오므로 실질 공백은 거의 없다.

## 오류 대비 구조 (2026-11-23)
- **공고 읽기는 한 길**(`reader.py`): 공고 페이지 → 첨부(PDF·HWP·HWPX·이미지·DOCX) 받기 → 글자 추출(PDF 글자 → pdfium → 그림 OCR / HWP 본문 / 이미지 OCR) → 임대조건·자격·마감. 출처마다 다른 건 `attachments()` 하나뿐.
- **보내기 전 관문**(`gate.py`): 카드마다 링크·조건·공고문 파일 점검. 실패면 간격 두고 3회 → 다른 방법 → 그래도 안 되면 카드에 `⚠️ 자동 점검 실패 — 무엇 — 왜`를 달고 보냄. 실패는 `failures.jsonl` 에 쌓임.
- **공고문 사본**(`archive.py`): 릴리스 `notice-files` 에 올리고 카드에 `📎 공고문 사본` 버튼. 비밀값 `SLACK_BOT_TOKEN`·`SLACK_CHANNEL_ID` 를 넣으면 카드 스레드에 파일도 올림(미검증).
- **배포는 `./deploy.sh` 로만**: `fix/` 가지 → Actions `시험 묶음`(tests 전체 + `tests/regress/cases.json` + 실제 사이트 접속) 전부 통과일 때만 main 반영, 실패면 슬랙 #알림 🔴.
- 수동 실행: `test_send=sh:313647`(1건 시험 발송), `site_report=1`(사이트 전체 점검표).
- 해결 에이전트: 맥 데스크톱 앱 예약 작업 `housing-fix-agent`(매일 15:10) — 지시문 galchi-automations/tasks/housing-fix-agent.md

# 설치

## 1. 저장소 만들기

**공개(Public) 저장소**여야 한다. 카카오가 이미지를 가져가려면 주소가 공개여야
하기 때문이다. 카드에는 공개된 모집공고 정보만 들어가고 개인정보는 없다.

```bash
gh repo create seoul-notice-bot --public --clone
# 이 폴더의 파일을 전부 복사한 뒤
git add . && git commit -m "init" && git push
```

## 2. 카카오 개발자 앱 등록 (무료)

1. https://developers.kakao.com → 내 애플리케이션 → **애플리케이션 추가하기**
2. 앱 이름 아무거나, 회사명은 본인 이름
3. **앱 키** 화면에서 `REST API 키` 복사 → 나중에 `KAKAO_REST_KEY` 로 쓴다
4. **카카오 로그인** 메뉴 → 활성화 **ON**
5. 같은 화면 **Redirect URI** 에 `https://localhost:3000` 등록
6. **동의항목** 메뉴 → `카카오톡 메시지 전송 (talk_message)` → **필수 동의**로 설정
7. **플랫폼** 메뉴 → Web 플랫폼 등록 → 사이트 도메인에 `https://cdn.jsdelivr.net` 추가
   (카드 이미지를 여기서 서빙한다)

## 3. 토큰 발급

### 3-1. 인가 코드 받기

아래 주소의 `{REST_API_KEY}` 를 바꿔서 브라우저 주소창에 붙여넣는다.

```
https://kauth.kakao.com/oauth/authorize?client_id={REST_API_KEY}&redirect_uri=https://localhost:3000&response_type=code&scope=talk_message
```

동의하면 `https://localhost:3000/?code=XXXXX` 로 넘어간다. 페이지는 안 열려도
된다. **주소창의 `code=` 뒤 값**만 복사한다. 이 코드는 몇 분 안에 만료되니
바로 다음 단계로 간다.

### 3-2. 리프레시 토큰 받기

터미널에서 (`{REST_API_KEY}`, `{CODE}` 교체):

```bash
curl -X POST "https://kauth.kakao.com/oauth/token" \
  -d "grant_type=authorization_code" \
  -d "client_id={REST_API_KEY}" \
  -d "redirect_uri=https://localhost:3000" \
  -d "code={CODE}"
```

응답의 **`refresh_token`** 값을 복사한다. (`access_token` 은 6시간짜리라
저장할 필요 없다. 봇이 매번 리프레시 토큰으로 새로 받는다.)

## 4. GitHub Secrets 등록

저장소 → Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 | 필수 |
|---|---|---|
| `KAKAO_REST_KEY` | 2단계의 REST API 키 | 필수 |
| `KAKAO_REFRESH_TOKEN` | 3단계의 refresh_token | 필수 |
| `GH_PAT` | `repo` 권한 Personal Access Token | 선택 |

`GH_PAT` 는 리프레시 토큰이 새로 발급될 때 자동으로 Secret 을 갱신하는 용도다.
넣지 않으면 두 달에 한 번쯤 3단계를 다시 해야 하고, 그때가 오면 봇이
카카오톡으로 알려준다.

## 5. 첫 실행

저장소 → Actions → **서울 임대주택 공고 알림** → Run workflow

- `dry_run` 에 `1` → 카톡 발송 없이 동작만 확인
- `rewind` 에 `6642` → 최근 공고 3건을 신규로 취급해 카드를 실제로 만들어 봄

정상이면 이후 **매일 07:47 KST + 금요일 18:17 KST 에 자동 실행**된다(정시 예약은 대기열에서 밀려 비켜 잡음). 금요일 저녁 실행은 새 공고만 보낸다(마감임박 재알림·'신규 없음' 줄 생략). 주말 실행을 넣은 이유: 엘리스 공실 공고는 금요일 오후에 올라와 일요일 18시에 마감된다(2026-11-23). GitHub 예약은 실제로 3~6시간 늦게 시작되는 일이 잦다(2026-11-10~23 실측: 11:29~13:56 KST 시작, 금요일 11/14·11/21 은 실행 자체가 없었음). 수동 실행 입력 `elyes_preview=1` 은 최근 4일 엘리스 글의 카드를 로그에만 찍는다(발송·상태 변경 없음).

# 동작 방식 메모

**신규 판정은 `boardId` 로 한다.** 게시판 화면의 번호(469 등)는 전체 건수에서
역산한 값이고, JSON 의 `rnum` 은 페이지 안 순번(1~10)일 뿐이다. 증가하는 고유
키는 `boardId` 하나뿐이라 이것만 믿는다.

**공고문 PDF 파싱은 최선 노력이다.** 청년안심주택 공고문은 표를 선 없이 그려서
일반적인 표 추출로는 안 잡힌다. 그래서 텍스트 줄을 창 단위로 훑어
`청년 309 5,700 50 7,600 43 9,500 36` 같은 줄에서 (보증금, 월세) 쌍을 뽑고,
앞뒤 줄에서 전용면적을 찾는다. 사업자마다 서식이 달라 실패할 수 있고,
그때는 카드에 "공고문 PDF 확인"으로 표시된다. 값이 틀려 보이면 항상 공고문 원문이
기준이다.

**보증금·월세는 범위로 표시된다.** 보증금 비율을 30/40/50% 중 선택할 수 있어서,
보증금을 올리면 월세가 내려간다. 카드의 `5,700~9,500 / 36~50` 은
"보증금 5,700만이면 월 50만, 9,500만이면 월 36만"이라는 뜻이다.

**카드 이미지는 저장소에 쌓인다.** 커밋된 파일을 jsDelivr CDN 으로 서빙해
카카오에 넘긴다. 60일 지난 카드는 워크플로가 자동으로 지운다.

## 슬랙 알림 (2026-11-18부터 슬랙만, 카톡은 꺼 둠)

- 카톡 발송은 워크플로의 `KAKAO_ENABLED: "0"` 으로 꺼 두었다. 코드는 그대로 있으니 `"1"` 로 바꾸면 되살아난다.
  카톡을 끈 동안에는 카카오 토큰 갱신도 하지 않으므로, 리프레시 토큰(약 60일)이 만료된 뒤 되살릴 때는 3단계 토큰 발급을 다시 해야 한다.
- Secret `SLACK_WEBHOOK_URL` 로 슬랙에 보낸다. 공고 1건 = 메시지 1개 (2026-11-18부터 표 형식):
  맨 위 한 줄 `(⚠️ D-N ·) 단지명 · 마감일시` → 표(타입 / 전용㎡ / 대상 / 보증금 비율 / 보증금(만원) / 월세(만원), 비율마다 한 행)
  → 단위 줄 → [공고 보기] [신청하기]. 표는 `data_table` 블록을 먼저 보내고, 거부되면 `table`, 그것도 거부되면 줄 목록으로 보낸다
  (로그에 `slack: 표 형식 … 로 보냄` 이 남는다). 휴대폰에서 열이 잘리면 워크플로 env `SLACK_TABLE_COLS: "compact"` 로 '대상' 열을 타입 옆에 붙인다.
- 금액·면적을 못 읽은 칸은 `확인 실패`. 전용 30㎡ 미만 타입은 표에서 빼고(`MIN_AREA`), 모든 타입이 미만인 공고는 보내지 않는다
  (로그에만 `30㎡ 미만으로 제외 N건`). 면적을 못 읽은 타입이 있으면 맨 위에 `📐 면적 확인 필요`.
- 보낼 공고가 2건 이상이면 먼저 `🏠 신규 N건 · 마감임박 N건` 한 줄을 따로 보낸다.
- 링크 미리보기(unfurl)는 끈다.
- 카톡이 꺼진 상태에서 슬랙 전송이 실패하거나 웹훅이 없으면 상태 파일을 저장하지 않고 실패로 끝난다(다음 실행에서 다시 보냄).
- 수동 실행에서 `slack_test` 를 `1` 로 주면 최근 실제 공고로 견본 3건(일반 · 마감임박 D-1 · 면적 확인 필요)을 보낸다. 마감일은 가상값(상태 파일·카톡·커밋 없음).
- 웹훅 주소는 로그에 찍지 않는다(실패 시 상태 코드·예외 종류만).
- 수동 실행 `dry_run=1` 은 아무것도 보내지 않고 상태 파일도 저장하지 않는다.
